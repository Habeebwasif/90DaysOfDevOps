# Linux File System Hierarchy (Important Directories) and Scenario-Based Practice
## Core Directories (Must Know):

* `/` - (Root)The top-level directory of the entire Linux file system hierarchy. I would use if i want to get into root of Linux file system.

* `/home` - Contains individual folders for normal users (ex: /home/ubuntu, /home/devops_user). I would use this when i
   need to access or manage files belonging to a normal user.
  
* `/root` - It is the home directory of the root user which has administrative privileges on the system. I would use this when i need to access
   configuration or personal files belonging to the root user. ex: .bashrc, .profile. (with sudo ofcourse).
  
* `/etc` - It contains system-wide configuration files used by Linux and installed services. ex: `passwd`, `hosts`, `shadow`.
  
  -`/etc/passwd` - i would use this becuase it helps me view information about system and user accounts.

  -`/etc/shadow` - i would use this when i need to view encrypted password information and account data. (using sudo)

* `/var/log` - It contains log files generated by the operating system, various applications and services. These logs are extremely useful for troubleshooting.

  -`/var/log/syslog` - i would use this when need to troubleshoot general system issues, monitor services.
 
  -`/var/log/auth.log` - i would use this when i need to check SSH login attempts, authentication failures or sudo activity.

* `/tmp` - It is mainly used to store temporary files created by applications and users.
  I would use it when i need temporary space for testing during daily tasks.

## Additional Directories (Good to Know):

* `/bin` - `/bin` and `/usr/bin` are essentially the same directory because /bin is a symbolic link (shortcut) pointing directly to /usr/bin.
  Historically, they were kept separate to ensure the operating system could boot using only a small, primary storage disk.
* `/usr/bin` - Contains many commonly used Linux commands and executable programs such as `ls`, `mkdir`, `mv`, `git` and `curl`.
* `/opt` - Contains optional or third-party software installed separately from the main Linux system. I would use this
  when i need to manage, configure, or troubleshoot third-party applications installed on a Linux server.
* `New thing i got to know` - On many modern Linux systems, /bin is actually a symbolic link to /usr/bin.
So commands such as ls, mkdir, and mv may appear under /usr/bin.

# Scenario-based practice:
## Scenario-1 - Service Not Starting
A service called 'ssh' failed to start after a server reboot. What commands would you run to diagnose the issue? Write at least 4 commands in order.

Step 1: `systemctl status ssh`
Why: I'll check the status if it is running or not.

Step 2: `journalctl -u ssh -n 50`
Why: I'll view the recent activity of logs failed.

Step 3: `systemctl is-enabled ssh`
Why: Check if the service startss automatically on boot.

## Scenario-2 - High CPU Usage
Your manager reports that the application server is slow. You SSH into the server. What commands would you run to identify which process is using high CPU?

Step 1: `top` or `htop`
Why: To checck all the running processes.

Step 2: `ps aux --sort=-%cpu | head -10`
Why: Sort processes by High-CPU usage. 

Step 3: `ps -p <pid> -f`
WHy: Shows detailed information about that specific process, including the command that started it.

## Scenario-3 - Finding Service Logs
A developer asks: "Where are the logs for the 'docker' service?". The service is managed by systemd. What commands would you use?

Step 1: `systemctl status ssh`
Why: Check service status first

Step 2: `journalctl -u ssh -n 50`
Why:  Views last 50 lines of logs

Step 3: `journalctl -u ssh -f`
Why: Follow logs in real-time.

## Scenario-4 - File Permissions Issue
A script at /home/user/backup.sh is not executing. When you run it: ./backup.sh You get: "Permission denied" What commands would you use to fix this?

Step 1: `ls -l hello.sh`
Why: Check current permissions of file. Look for: -rw-r--r-- (notice no 'x' = not executable).

Step 2: `chmod +x /home/ubuntu/hello.sh`
Why: Add execute permission to file.

Step 3: `ls -l hello.sh`
Why: Verify it worked. Look for: -rwxr-xr-x (notice 'x' = executable).

Step 4: `./hello.sh`
Why: Run it.
